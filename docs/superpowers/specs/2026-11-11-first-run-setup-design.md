# 첫 실행 설정 화면 + 앱 내 AI 연결 설정 — 설계

작성일: 2026-11-11 · 상태: 검토 대기

## 목적

앱을 처음 켠 사람이 환경변수나 문서를 몰라도 **언어**와 **AI 연결(API 키)** 을 정하고 바로 쓸 수 있게 한다. 두 번째 실행부터는 설정 화면 없이 본 앱이 뜬다.

성공 기준:
- 첫 실행에서 설정 화면이 본 앱보다 먼저 나오고, 끝내면 본 앱으로 넘어간다.
- AI 연결은 건너뛸 수 있고, 나중에 설정 화면에서 넣거나 바꾸거나 지울 수 있다.
- API 키는 평문으로 디스크에 남지 않고, 화면 쪽 코드로 되돌아오지 않는다.

## 사용자가 정한 것 / 내가 가정한 것

사용자가 정한 것:
- 첫 실행에 기본 설정 화면을 먼저 보여 준다(언어, API 키 등).
- API 키는 앱 안에 암호화해서 저장한다.

가정(틀리면 알려 주세요):
- "API 키"는 AI 분석 보조용 제공자 키다. 지금은 환경변수 `APEX_DESKTOP_AI_CONFIG` + 키 변수로만 설정한다.
- 설정 단계는 **언어 → AI 연결(선택)** 두 개다. 분석자 이름, OCR·STT, 서버 계정 로그인은 넣지 않는다(기존 설정 화면에 이미 있음).
- "설정 창"은 별도 OS 창이 아니라 같은 창 안의 전체 화면이다.
- 이미 앱을 쓰던 사람도 업데이트 후 한 번은 이 화면을 본다. (영어 OS를 쓰는 한국어 사용자가 여기서 한국어를 고를 수 있다.)

## 바뀌는 원칙

기존 문서는 "렌더러에서 키나 접속 주소를 전달하지 않는다"고 적고 있다. 이 설계는 그 원칙을 다음으로 바꾼다:

> 키는 화면 → 앱 본체(Electron main)로 **저장할 때 한 번만** 지나간다. 본체는 키를 OS 키체인으로 암호화해 저장하고, 화면에는 "키가 있다/없다"만 돌려준다.

서버 계정 로그인의 비밀번호가 이미 같은 경로(`apex:login`)를 쓴다.

## 구조

Python 엔진은 **바꾸지 않는다.** 엔진은 지금도 요청마다 환경변수에서 AI 설정을 읽으므로, 본체가 엔진을 띄울 때 환경변수로 넣어 주면 된다.

```
설정 화면(렌더러) ──IPC──▶ Electron main ──(암호화 저장)──▶ userData/ai-connection.json
                              │
                              └─ 엔진 실행 시 env 주입:
                                 APEX_DESKTOP_AI_CONFIG     = {provider_id, base_url, model_id, api_key_env, …}
                                 APEX_DESKTOP_AI_STORED_KEY = <복호화한 키>
```

- `provider_id`는 고정값 `apex-desktop`, `api_key_env`는 고정값 `APEX_DESKTOP_AI_STORED_KEY`다. 사용자가 직접 쓰는 `APEX_AI_API_KEY` 같은 변수와 겹치지 않게 전용 이름을 쓴다.

### 1. 저장 (`frontend/electron/aiConnection.ts`, 새 파일)

Electron에 의존하지 않는 순수 모듈로 만들고, 암호화·파일 접근은 인자로 주입한다(테스트 가능).

- 저장 내용: `{ base_url, model_id, temperature, max_output, timeout, key }`. `key`는 `safeStorage.encryptString()` 결과를 base64로 담는다.
- 위치: `app.getPath("userData")/ai-connection.json`, 권한 `0600`, 임시 파일에 쓴 뒤 rename.
- `safeStorage.isEncryptionAvailable()`이 false면 **저장하지 않고** `AI_KEY_STORAGE_UNAVAILABLE`로 거절한다. 평문 저장 경로는 없다.
- 파일이 깨졌거나 복호화에 실패하면 "설정 안 됨"으로 취급하고 앱은 정상 시작한다.

검증 규칙:
- `base_url`: `https:`만 허용. 단 `127.0.0.1`·`localhost`는 `http:` 허용(로컬 모델 서버). 사용자명·비밀번호·쿼리·해시가 있으면 거절.
- `model_id`: 1–256자.
- `api_key`: 1–4096자, 제어 문자 없음. 이미 저장된 키가 있고 입력이 비어 있으면 기존 키를 유지한다.
- `temperature` 0–2(기본 0), `max_output` 1–200000(기본 4096), `timeout` 1–600초(기본 30). 엔진의 `AiProviderRuntimeConfig` 범위와 같다.
- 위반 시 `AI_CONNECTION_INVALID`.

### 2. 환경변수 우선순위

실행 환경에 `APEX_DESKTOP_AI_CONFIG`가 이미 있으면 **그쪽이 이긴다.** 본체는 덮어쓰지 않고, 화면은 "환경변수로 관리됨"을 보여 주며 입력을 막는다(분석기 설정의 `managed`와 같은 방식). 기존 사용법은 그대로 동작한다.

### 3. 엔진 재시작

키나 주소를 저장·삭제하면 본체가 엔진을 다시 띄운다(환경변수는 프로세스 시작 시에만 들어가므로).

- `restartBackend()`: 기존 프로세스를 종료 → 종료 확인 → 새 env로 시작 → 준비될 때까지 대기(최대 90초).
- 이전 프로세스의 `exit` 이벤트가 새 프로세스의 상태를 지우지 않도록 세대 번호로 구분한다.
- 진행 중인 분석 작업이 있으면 중단되므로, 설정 화면의 AI 카드는 **작업이 도는 동안 저장·삭제 버튼을 막고** 이유를 적는다. 첫 실행 화면에서는 작업이 없으니 해당 없음.

### 4. IPC (`window.apex`에 추가)

| 메서드 | 반환 |
|---|---|
| `aiConnection()` | `{ configured, managed, has_key, storage_available, base_url, model_id, temperature, max_output, timeout }` |
| `saveAiConnection({ base_url, model_id, api_key?, temperature?, max_output?, timeout? })` | 위와 같은 상태 |
| `clearAiConnection()` | 위와 같은 상태 |

- `configured`는 "엔진이 AI 설정을 받는다"는 뜻이다(저장된 연결이 유효하거나 환경변수로 관리 중). `has_key`는 앱에 저장된 키가 있는지다.
- 환경변수로 관리 중일 때 저장·삭제를 요청하면 `AI_CONNECTION_MANAGED`로 거절한다.
- 키는 어떤 응답에도 넣지 않는다. 로그에도 남기지 않는다.
- 기존 `handle()` 래퍼의 발신자 검증(`trusted`)을 그대로 쓴다.
- 데모 브리지(웹 미리보기)는 `configured: false`를 돌려주고 저장은 `DEMO_READ_ONLY`로 거절한다.

### 5. 화면

**`FirstRunSetup` (새 컴포넌트, `main.tsx`에서 `<App />`을 감쌈)**
- `localStorage["apex.setupComplete"] === "1"`이면 바로 `<App />`.
- 저장소를 읽을 수 없으면 설정 화면을 건너뛴다(매번 뜨는 것을 막기 위해).
- 1단계 언어: 한국어 / English 두 선택지. OS 언어로 미리 선택돼 있고, 고르면 화면이 바로 그 언어로 바뀐다. 제목은 두 언어로 함께 표기.
- 2단계 AI 연결(선택): 접속 주소, 모델 이름, API 키(비밀번호 입력란). 고급 설정(temperature, 최대 출력, 제한 시간)은 접어 둔다. 버튼은 "저장하고 시작"과 "나중에 설정".
  - 환경변수로 관리 중이면 입력란 대신 상태만 보여 주고 "시작".
  - 데스크톱 브리지가 없으면(웹 미리보기) 이 단계를 건너뛴다.
  - 암호화 저장을 쓸 수 없으면 그 이유를 보여 주고 "나중에 설정"만 남긴다.
- 끝내면 플래그를 저장하고 본 앱으로.

**설정 화면의 "AI 연결" 카드 (언어 카드 아래)**
- 같은 입력 폼을 재사용한다(`AiConnectionForm`).
- 현재 상태(설정됨 / 설정 안 됨 / 환경변수로 관리됨), 저장, 연결 삭제.
- 키 입력란은 항상 비어 있고, 저장된 키가 있으면 "저장된 키 유지" 안내를 보여 준다.

기존 테스트는 `<App />`을 직접 렌더링하므로 첫 실행 화면의 영향을 받지 않는다.

### 6. 문구

- 새 문구는 모두 한국어·영어 문구 사전(`locales/*/setup.ts`)에 넣는다.
- 새 오류 코드: `AI_CONNECTION_INVALID`, `AI_KEY_STORAGE_UNAVAILABLE`, `AI_CONNECTION_MANAGED`.
- 기존 `AI_CONFIGURATION_INVALID` 문구에 "설정의 AI 연결"을 덧붙인다(환경변수만 안내하던 문장).

## 보안 정리

- 키가 머무는 곳: 입력란(저장 직후 비움) → IPC 한 번 → 본체 메모리 → 암호화 파일 → 엔진 프로세스 환경변수.
- 엔진 환경변수에 키가 있는 것은 지금의 환경변수 방식과 같다.
- 평문 저장 없음, 화면으로 되돌려 주지 않음, 로그 없음.
- `http://`(로컬 제외) 주소를 거절해 키가 평문으로 나가는 것을 막는다.
- AI로 무엇을 보낼지는 여전히 사건별 AI 데이터 정책이 결정한다. 이 설계는 "연결"만 다루고 정책 기본값(차단)을 바꾸지 않는다.

## 테스트

- `aiConnection.ts` 단위 테스트: 검증 규칙, 암호화 불가 시 거절, 깨진 파일, 키 유지, 환경변수 우선, 엔진 env 조립.
- `FirstRunSetup`: 첫 실행에 표시 / 완료 후 재실행 시 미표시 / 언어 선택 즉시 반영 / 건너뛰기 / 저장 시 브리지 호출 값 / 키가 화면에 다시 나타나지 않음 / 관리 상태 / 브리지 없음 / 저장소 실패.
- 설정 카드: 상태 표시, 작업 중 버튼 비활성, 삭제.
- 패키징 스모크 테스트(`--apex-smoke-test`)는 `#root`에 글자가 있고 IPC가 되는지만 보므로 첫 실행 화면에서도 통과한다. 확인 항목에 포함.
- 실제 앱 확인: 개발 모드로 띄워 가짜 키와 로컬 주소로 저장 → 엔진 재시작 → AI 상태가 "설정됨"으로 바뀌는지. 실제 키는 쓰지 않는다.

## 범위 밖

- 연결 테스트 버튼(실제 제공자 호출). 저장 후 상태 표시로 대신한다.
- 제공자 목록·프리셋. 접속 주소와 모델 이름을 직접 입력한다(OpenAI 호환).

- 설정 화면 다시 보기 메뉴.
- 엔진을 재시작하지 않고 키를 바꾸는 방법.
- Linux 키체인 대응(지원 플랫폼은 Windows·macOS).
