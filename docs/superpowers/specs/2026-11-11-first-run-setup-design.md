# 첫 실행 설정 창 + 앱 내 AI 연결 설정 — 설계

작성일: 2026-11-11 · 상태: 승인됨 (2026-11-11, 설정 항목 추가·별도 창 반영)

## 목적

앱을 처음 켠 사람이 환경변수나 문서를 몰라도 **작은 설정 창**에서 기본값을 정하고 바로 쓸 수 있게 한다. 설정을 마치면 설정 창이 닫히고 본 앱 창이 열린다. 두 번째 실행부터는 본 앱이 바로 뜬다.

성공 기준:
- 첫 실행에서 작은 설정 창이 먼저 뜨고, 끝내면 본 앱 창으로 넘어간다.
- 언어 외의 단계는 모두 건너뛸 수 있고, 나중에 본 앱의 설정 화면에서 바꿀 수 있다.
- API 키는 평문으로 디스크에 남지 않고, 화면 쪽 코드로 되돌아오지 않는다.

## 결정 사항

사용자가 정한 것:
- 첫 실행에 **별도의 작은 창**으로 기본 설정을 먼저 받고, 끝나면 본 앱으로 넘어간다.
- 설정 단계: **언어 → 분석자 이름 → AI 연결 → OCR·음성 인식 → 서버 계정**.
- API 키는 앱 안에 암호화해서 저장한다.
- 이미 앱을 쓰던 사람도 업데이트 후 한 번은 이 창을 본다.
- 키를 저장·삭제하면 분석 엔진을 다시 시작한다. 분석 작업이 도는 동안에는 본 앱 설정 화면의 저장·삭제 버튼을 막는다.
- 환경변수 `APEX_DESKTOP_AI_CONFIG`가 있으면 그쪽이 우선하고, 화면은 "환경변수로 관리됨"만 보여 준다.
- 접속 주소는 `https://`만 받는다(`localhost`·`127.0.0.1`은 `http://` 허용).
- 연결 테스트 버튼과 제공자 프리셋은 넣지 않는다.

구현하면서 정한 것:
- "분석자 이름"은 새 사건을 만들 때 **미리 채워지는 기본값**이다(사건마다 바꿀 수 있다).
- 서버 계정 로그인은 지금도 앱을 끄면 풀린다(세션을 메모리에만 둔다). 설정 창에서 로그인해도 그 실행 동안만 유지된다. 이 동작은 바꾸지 않고 화면에 그렇게 적는다.
- 설정 창을 끝내지 않고 닫으면 앱이 종료되고, 다음 실행에 설정 창이 다시 뜬다.

## 바뀌는 원칙

기존 문서는 "렌더러에서 키나 접속 주소를 전달하지 않는다"고 적고 있다. 이 설계는 그 원칙을 다음으로 바꾼다:

> 키는 화면 → 앱 본체(Electron main)로 **저장할 때 한 번만** 지나간다. 본체는 키를 OS 키체인으로 암호화해 저장하고, 화면에는 "키가 있다/없다"만 돌려준다.

서버 계정 로그인의 비밀번호가 이미 같은 경로(`apex:login`)를 쓴다.

## 구조

Python 엔진은 **바꾸지 않는다.**

```
[설정 창 620×720]  ─┐
                    ├─IPC─▶ Electron main ─▶ userData/app-state.json      (설정 완료 여부)
[본 앱 창]         ─┘                     ─▶ userData/ai-connection.json  (암호화된 키 + 접속 정보)
                                          ─▶ 엔진 실행 시 env 주입
                                             APEX_DESKTOP_AI_CONFIG     = {provider_id, base_url, model_id, api_key_env, …}
                                             APEX_DESKTOP_AI_STORED_KEY = <복호화한 키>
```

### 1. 창 흐름 (`frontend/electron/main.ts`)

- 시작할 때 `app-state.json`의 `setup_complete`를 본다.
  - 없거나 false → **설정 창**만 연다: 620×720, 크기 조절·최대화 불가, 화면 가운데.
  - true → 지금처럼 본 앱 창을 연다.
  - `--apex-smoke-test`(패키징 CI)에서는 설정 창을 건너뛰고 본 앱 창을 연다.
- 두 창은 같은 `index.html`을 쓴다. 설정 창은 `#setup`을 붙여 연다.
- 설정 창이 `completeSetup()`을 호출하면 본체가 완료를 기록하고 → 본 앱 창을 만든 뒤 → 설정 창을 닫는다(순서를 지켜 "모든 창이 닫힘 → 종료"를 피한다).
- 발신자 검증(`trusted`)은 설정 창과 본 앱 창 둘 다 허용하도록 바꾼다. `completeSetup`은 설정 창에서 온 것만 받는다.
- 파일 선택 대화상자는 요청한 창을 부모로 연다(지금은 본 앱 창 고정).
- 엔진은 지금처럼 앱 시작과 함께 뜬다. 설정 창의 OCR·음성 인식 단계와 AI 저장이 엔진을 쓴다.
- 창 생성·전환 판단은 테스트할 수 있게 순수 함수로 뺀다(`frontend/electron/appState.ts`).

### 2. 설정 창 화면 (`frontend/src/setup/`)

`main.tsx`가 `location.hash === "#setup"`이면 `<SetupApp />`을, 아니면 `<App />`을 렌더링한다. 둘 다 `I18nProvider` 안이다. 기존 테스트는 `<App />`을 직접 렌더링하므로 영향을 받지 않는다.

왼쪽 레일에 로고와 5단계 목록(현재·완료 표시, 눌러서 이동)을 두고, 오른쪽에 한 번에 한 단계씩 보여 준다. 아래에 `이전` / `건너뛰기` / `다음`(마지막은 `시작`)과 "2 / 5" 표시를 둔다. AI 단계의 주 버튼은 `저장하고 다음`이다. (2026-11-11 사용자 요청으로 화면을 다시 디자인함. 규칙은 DESIGN.md의 "First-run setup window".)

| 단계 | 내용 | 저장 위치 |
|---|---|---|
| 1 언어 | 한국어 / English. OS 언어로 미리 선택. 고르면 창이 바로 그 언어로 바뀜. 제목은 두 언어 병기 | `localStorage["apex.locale"]` (기존) |
| 2 분석자 이름 | 선택 입력. 새 사건의 "분석자 이름" 기본값 | `localStorage["apex.examinerName"]` |
| 3 AI 연결 | 접속 주소, 모델 이름, API 키(비밀번호 입력란). 고급 설정(temperature·최대 출력·제한 시간)은 접어 둠 | 본체가 암호화 저장 |
| 4 OCR·음성 인식 | 기존 `MachineSettings`를 `compact` 형태(카드 틀·제목·소개 문단 없이)로 사용. 기본값으로 동작하므로 손대지 않고 넘어가도 됨 | 엔진(기존) |
| 5 서버 계정 | 기존 `AccountPanel`을 `compact` 형태로 사용. 로그인이 앱을 끌 때까지만 유지된다는 안내는 단계 설명에 둔다 | 본체 메모리(기존) |

- 두 창은 같은 출처(origin)라 `localStorage`를 공유한다. 설정 창에서 고른 언어·분석자 이름을 본 앱 창이 그대로 읽는다.
- AI 단계: 환경변수로 관리 중이면 입력란 대신 상태만 보여 준다. 암호화 저장을 쓸 수 없으면 이유를 보여 주고 건너뛰게 한다.
- 저장 실패(검증 오류 등)는 그 단계에 머물며 오류를 보여 준다. 건너뛰기는 항상 가능하다.

### 3. 본 앱 설정 화면에 추가

- **AI 연결 카드**(언어 카드 아래): 설정 창과 같은 폼(`AiConnectionForm`)을 재사용. 현재 상태(설정됨 / 설정 안 됨 / 환경변수로 관리됨), 저장, 연결 삭제. 분석 작업이 도는 동안 저장·삭제를 막고 이유를 적는다. 키 입력란은 항상 비어 있고, 저장된 키가 있으면 "비워 두면 저장된 키를 유지합니다" 안내.
- **기본 분석자 이름**: 언어 카드 옆에 입력란 하나.
- 새 사건 대화상자의 "분석자 이름"이 이 값으로 미리 채워진다.

### 4. AI 연결 저장 (`frontend/electron/aiConnection.ts`, 새 파일)

Electron에 의존하지 않는 순수 모듈. 암호화·파일 접근은 인자로 주입한다.

- 저장 내용: `{ base_url, model_id, temperature, max_output, timeout, key }`. `key`는 `safeStorage.encryptString()` 결과의 base64.
- 위치: `userData/ai-connection.json`, 권한 `0600`, 임시 파일에 쓴 뒤 rename.
- `safeStorage.isEncryptionAvailable()`이 false면 **저장하지 않고** `AI_KEY_STORAGE_UNAVAILABLE`. 평문 저장 경로는 없다.
- 파일이 깨졌거나 복호화에 실패하면 "설정 안 됨"으로 취급하고 앱은 정상 시작한다.
- `provider_id`는 고정값 `apex-desktop`, `api_key_env`는 고정값 `APEX_DESKTOP_AI_STORED_KEY`. 사용자가 직접 쓰는 `APEX_AI_API_KEY`와 겹치지 않게 전용 이름을 쓴다.

검증(위반 시 `AI_CONNECTION_INVALID`):
- `base_url`: `https:`만. `127.0.0.1`·`localhost`는 `http:` 허용. 사용자명·비밀번호·쿼리·해시가 있으면 거절.
- `model_id`: 1–256자.
- `api_key`: 1–4096자, 제어 문자 없음. 저장된 키가 있고 입력이 비어 있으면 기존 키 유지.
- `temperature` 0–2(기본 0), `max_output` 1–200000(기본 4096), `timeout` 1–600초(기본 30).

환경변수 우선: 실행 환경에 `APEX_DESKTOP_AI_CONFIG`가 있으면 본체는 덮어쓰지 않고, 저장·삭제 요청은 `AI_CONNECTION_MANAGED`로 거절한다.

### 5. 엔진 재시작

- `restartBackend()`: 기존 프로세스 종료 → 종료 확인 → 새 env로 시작 → 준비될 때까지 대기(최대 90초).
- 이전 프로세스의 `exit` 이벤트가 새 프로세스의 상태를 지우지 않도록 세대 번호로 구분한다.

### 6. IPC (`window.apex`에 추가)

| 메서드 | 반환 |
|---|---|
| `aiConnection()` | `{ configured, managed, has_key, storage_available, base_url, model_id, temperature, max_output, timeout }` |
| `saveAiConnection({ base_url, model_id, api_key?, temperature?, max_output?, timeout? })` | 위와 같은 상태 |
| `clearAiConnection()` | 위와 같은 상태 |
| `completeSetup()` | `null` (설정 창에서만 허용) |

- `configured`: 엔진이 AI 설정을 받는가(저장된 연결이 유효하거나 환경변수로 관리 중). `has_key`: 앱에 저장된 키가 있는가.
- 키는 어떤 응답에도 넣지 않는다. 로그에도 남기지 않는다.
- 데모 브리지(웹 미리보기)는 `configured: false`를 돌려주고 저장은 `DEMO_READ_ONLY`로 거절한다.

### 7. 문구

- 새 문구는 모두 한국어·영어 문구 사전(`locales/*/setup.ts`)에 넣는다.
- 새 오류 코드: `AI_CONNECTION_INVALID`, `AI_KEY_STORAGE_UNAVAILABLE`, `AI_CONNECTION_MANAGED`.
- 기존 `AI_CONFIGURATION_INVALID` 문구 끝에 "설정의 AI 연결"을 덧붙인다(앞부분은 그대로 둬서 기존 테스트의 일치 조건을 유지한다).

## 보안 정리

- 키가 머무는 곳: 입력란(저장 직후 비움) → IPC 한 번 → 본체 메모리 → 암호화 파일 → 엔진 프로세스 환경변수.
- 엔진 환경변수에 키가 있는 것은 지금의 환경변수 방식과 같다.
- 평문 저장 없음, 화면으로 되돌려 주지 않음, 로그 없음.
- `http://`(로컬 제외) 주소를 거절해 키가 평문으로 나가는 것을 막는다.
- AI로 무엇을 보낼지는 여전히 사건별 AI 데이터 정책이 결정한다. 이 설계는 "연결"만 다루고 정책 기본값(차단)을 바꾸지 않는다.
- 설정 창도 본 앱 창과 같은 보안 설정(contextIsolation, sandbox, 외부 이동·새 창 차단, 권한 요청 거부)을 쓴다.

## 테스트

- `aiConnection.ts`: 검증 규칙, 암호화 불가 시 거절, 깨진 파일, 키 유지, 환경변수 우선, 엔진 env 조립.
- `appState.ts`: 완료 플래그 읽기/쓰기, 깨진 파일, 스모크 테스트 시 설정 창 생략 판단.
- `SetupApp`: 단계 이동, 언어 선택 즉시 반영, 분석자 이름 저장, AI 저장 시 브리지 호출 값, 키가 화면에 다시 나타나지 않음, 관리 상태, 건너뛰기, `시작`이 `completeSetup`을 호출.
- 본 앱: AI 연결 카드(상태, 작업 중 비활성, 삭제), 기본 분석자 이름이 새 사건에 채워짐.
- 실제 앱 확인: 개발 모드로 띄워 설정 창 → 본 앱 전환, 가짜 키와 로컬 주소로 저장 → 엔진 재시작 → AI 상태 변화, 두 번째 실행에 설정 창이 안 뜨는지. 실제 키는 쓰지 않는다. 화면은 Electron 원격 디버깅 포트로 캡처한다.
